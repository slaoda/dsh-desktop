# Windows Harness 管理器规格

[English](WINDOWS_MANAGER_SPEC.md) | 简体中文

状态：已批准实施

## 目标

将 DSH Desktop 改造成面向非技术用户的安全、可一键使用的 Windows 11 x64 DeepSeek Harness 管理器。应用自带运行环境，可保留多个官方 Harness 版本，检测符合条件的既有安装，并让更新过程可以恢复。

## 产品范围

- 提供图形化 Windows `.exe` 安装程序，允许用户自定义应用安装目录。
- 内置 Node.js 和包管理器。正常使用不依赖终端、系统 Node.js、npm 或 pnpm。
- Harness 只能监听 `127.0.0.1`，不得暴露到局域网。
- 用户可安装、保留、切换、启动、停止和卸载指定的官方 Harness 版本。
- 提供稳定版、预览版和全部版本三个渠道。安装和切换始终由用户明确触发。
- 检测独立/全局的既有 Harness 安装，经用户明确确认后原地管理。项目内依赖只展示、不可修改。
- 应用卸载与 Harness 版本卸载相互独立。正在运行的版本不得卸载。
- 支持系统代理、可选手动代理和可选的 npm 兼容镜像。
- 展示下载进度，重试可恢复故障，并在发布安装前校验官方包。
- 支持关闭到托盘和可选的开机启动。

## 可恢复更新

在可能影响用户数据的版本切换前，管理器会备份用户选择的 Harness 主目录。备份排除凭据文件，默认只保留最近三个自动/手动备份。候选版本必须先成功启动并通过健康检查，之后才提交版本选择。若启动失败，旧版本仍保持选中并可重新启动。未完成的事务会在下次启动时被检测。

已知迁移只能通过管理器内置的白名单迁移标识执行。遇到未知的破坏性变更时必须明确告警；下载的包不能提供或执行管理器迁移脚本。

恢复支持“仅配置”和“配置及会话”两种模式，凭据永远不会被恢复。

## 既有安装所有权策略

只有同时满足以下条件的安装才可管理：

1. 包清单确认它是官方 `@deepseek-ai/dsh` 包，且版本号是有效语义版本。
2. CLI 入口解析后位于该包根目录内。
3. 它是用户明确选择的独立安装，或已验证的 npm 全局安装。
4. 管理器通过内置 Node.js 和解析后的绝对 CLI 路径启动，且 `shell: false`。

项目内依赖和来源不明的 PATH 项只读展示。只有验证通过的 npm 全局安装可原地卸载，并使用对应包管理器的明确全局卸载命令。管理器绝不递归删除外部包根目录。

## 数据与安全边界

- API Key 在官方 Harness 界面中输入，管理器不内置、不展示、不记录、不备份也不恢复。
- 文件路径、版本号、URL、IPC 输入、包清单和进程输出均按不可信数据处理，并在主进程重新校验。
- 镜像地址只能使用 HTTP 或 HTTPS，且不得包含嵌入式凭据。安装后校验官方包身份和版本。
- 日志会隐藏凭据和代理认证信息。诊断日志、事务日志、备份和托管版本位于应用自有数据目录。
- 安装和备份前执行磁盘空间预检查。
- 卸载和恢复必须在 GUI 中明确确认。

## 主要用户流程

1. 首次启动检测环境，显示既有安装，并推荐版本渠道。
2. 用户选择应用托管版本，或明确选择符合条件的既有安装。
3. 启动时等待本机回环健康检查，打开官方 Harness UI，并在其中引导首次配置 API Key。
4. 更新时先备份，再安装且不覆盖旧版本；候选版本通过健康检查后才提交切换。
5. 失败时保留旧选择和备份，并提供清晰的恢复操作。

## 验收标准

- 全新 Windows 11 x64 电脑无需预装运行环境即可安装并启动 Harness。
- 稳定版/预览版/全部版本能正确区分预发布版本，同时仍可安装指定历史版本。
- 候选版本启动失败时不能替换当前正常版本。
- 正在运行的版本不能卸载。
- 凭据测试文件不会出现在备份和日志中。
- 项目内检测结果不能进入破坏性管理流程。
- 打包后的应用仅监听 `127.0.0.1`，可从中断的安装/更新中恢复，并通过仓库验证和打包冒烟测试。
